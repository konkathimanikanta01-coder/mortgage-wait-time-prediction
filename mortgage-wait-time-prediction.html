#Part III: Supervised Learning – Predicting Wait Time Between Loan Approval and Advance

Predicting mortgage approval-to-disbursement wait times provides value to lenders (resource planning) and applicants (reduced uncertainty). This analysis uses a dataset of historical mortgage applications and explores two modeling strategies to predict the wait time (in days) between approval and disbursement: • Strategy A: A full-model approach using the complete dataset with appropriate feature imputation. • Strategy B: A segmented approach that trains separate models for joint and single applicants.

Limitations • App2-related features were often missing and filled via imputation, which introduces uncertainty. • Ignores structural differences between joint and single applicants ——————————————————————————– #Strategy B: Split by Applicant Type (Joint vs Single)

Motivation: The dataset segmentation by applicant type addresses structural differences between joint and single applications. Joint applications contain additional features for the second applicant (App2_Age, App2_G, App2_Income) that don’t apply to single applicants. Including these variables in one unified model would introduce irrelevant feature noise and reduce predictive accuracy. This led to creating two separate models: a Single Applicants model (excluding all App2 variables) and a Joint Applicants model (retaining these variables).

df_model$Joint <- as.factor(df_model$Joint)

Converts the Joint column into a factor (to use “0” and “1” as levels).

The data is split into two groups: single applicants, where Joint == 0 indicating they are applying alone, and joint applicants, where Joint == 1 indicating they are applying with a second applicant.

#Modeling Function

run_model_eval <- function(df, model_type = "rf") {
  set.seed(123)
  index <- createDataPartition(df$wait_time_days, p = 0.8, list = FALSE)
  train <- df[index, ] %>% droplevels()
  test  <- df[-index, ] %>% droplevels()

  if (model_type == "rf") {
    model <- randomForest(wait_time_days ~ ., data = train, ntree = 500, importance = TRUE)
    pred <- predict(model, test)
  } else {
    stop("Unsupported model type")
  }

  rmse <- sqrt(mean((pred - test$wait_time_days)^2))
  mae  <- mean(abs(pred - test$wait_time_days))
  r2   <- cor(pred, test$wait_time_days)^2

  list(model = model, RMSE = rmse, MAE = mae, R2 = r2, test_data = test)
}

Both models were trained using Random Forest to ensure consistency in evaluation and comparison.Each subset is used to train a dedicated Random Forest model using an 80/20 train-test split. A helper function run_model_eval is used to train the model, generate predictions, and calculate performance metrics (RMSE, MAE, R²). #Run for both segments

plot_predicted_vs_actual <- function(model, test_data, segment_name) {

#Recommendation Based on performance and domain logic, I recommend adopting: Strategy B (Segmented Modeling) for production. • It avoids forcing App2-related features into irrelevant cases. • It yields higher R² for joint applicants, who likely represent more financially significant applications. • Its design better reflects business rules and real-world complexity.

#Limitations: • The models cannot account for external economic factors or policy changes that might influence processing times. • Internal workflow or staffing variables were likely not captured in the dataset but may significantly impact wait times.

#Conclusion By comparing a full-model strategy (Strategy A) with a segmented modeling strategy (Strategy B), we showed that contextual segmentation improves predictive accuracy, particularly when modeling behaviorally and structurally distinct groups (single vs joint applicants). The best-performing model was the Random Forest in Strategy B (Joint applicants) with an R² of 0.40, while the unified model in Strategy A yielded a maximum R² of 0.35. These results suggest that data segmentation by applicant type is not only reasonable but beneficial. In practical deployment, a hybrid approach using a routing logic (based on joint/single status) could deliver optimal predictions while maintaining model simplicity for each segment.
